## Problem (Mary + audit — facts)

1. **[P0-audit] Settings engine gate lies:** the super_admin-only guard in `ops.ts:26/:109` tests prefix **`engine.`** but every real engine key is **`public.engine_*`** (`settings.ts:22-27`, seed 0005) — role `admin` (which holds `settings.write`, lacks `settings.engine`, pinned `admin-rbac.test.ts:106-131`) can rewrite the live calculation engine today. Untested. Security-first owner brief → fix + pin this phase.
2. **[P0-audit] `confirmed_at` is dead code:** nothing ever writes `newsletter_subscribers.confirmed_at`; the dashboard "Confirmed subscribers" stat (`stats.ts:90`, `index.astro:29`) is structurally 0. Double opt-in is unimplemented and needs email (Resend key = owner-gated).
3. **[P1-audit] Catalog delete mismatch:** FE dialog says "soft delete — hidden from the site" (`catalog.astro:213`) but backend `DELETE` hard-deletes rows (`catalog.ts:2-4/:208/:359`) — violates the owner's backup-before-delete rule and orphans `puja_requests.puja_id` via FK SET NULL.
4. **[P1] Catalog surfaces are read-mostly:** no pagination/search on either GET; **not editable via the panel:** astrologer `is_available/availability_label/sort_order` (+ `accent` clobbered to "primary" on every save, `catalog.astro:177/:186`); puja `name_hi/samagri/purpose/sort_order`; `includes` squashed to a comma string; `session_types` null-edit writes the literal string `"[]"` which the validator then rejects (`catalog.astro:143`). Mass-assignment spreads remain in the write paths (Winston §6).
5. **[P1] Subscribers screen doesn't exist:** `newsletter.read/.write/.delete` capabilities are granted (`rbac.ts`) but referenced by **no route**; the only surface is one export button on settings.astro. Export silently truncates at 10000 (no `X-Export-Capped`, unlike inbox export). DPDP permanent delete: impossible from the panel.
6. **[P1] `nav.write` is dead:** nav lives in checked-in `frontend/src/data/navigation.ts` (D12 boundary); no endpoint, no storage, no UI. Winston §10 (decision **D3 = yes**): move nav + homepage-section config to `site_settings` keys, frontend keeps checked-in fallback, reads override at build, save triggers the existing deploy hook.
7. **[P1] Astrologer consent:** no `listing_consent_confirmed_at`; all 6 rows `is_sample=true` and publicly listed as if real. Winston §6: public listing requires `is_active AND consent NOT NULL`; owner decides sample-vs-real — **default until owner answers: samples become unlisted (honest empty state), consent checkbox in panel**.
8. **[P1] Horoscope content screen (Mary item 6):** no lang filter/field (hi rows unmanageable), 100-row edit cap vs 384 rows (most unopenable), wrong sort, cron never generates the enum-legal `yesterday`/`tomorrow` periods (0 rows), no row delete. **Blocks screen:** `kundli.` prefix hardcoded (`blocks.astro:56` — 12 other groups unreachable) and save drops non-title/body payload keys.
9. **[P2] Cross-cutting:** settings GET returns every row (incl. non-`public.%` internals) to any `settings.read`; no rate limit on settings writes; FE renders write controls for roles that will 403 (only inbox/users gate affordances); no DELETE tests for catalog; no engine-403 test.

## Acceptance criteria (binding)

1. **[P0] Engine gate:** `PUT /admin/settings/public.engine.*` as role `admin` → 403 (pinned test); as super_admin → 200; non-engine `public.*` keys still writable by admin; registry-driven PUT rejects unknown keys 404 and wrong shapes 400 with field errors; settings writes rate-limited 60/min/user.
2. **Catalog:** POST/PATCH whitelists only (fuzz a payload with an unknown field → ignored, not stored); every §Scope-1 field round-trips incl. JSONB validation errors; list paginates with `meta.total` + q + status filter; GET-by-id works; DELETE soft-deletes (row still in DB, `deleted_at` set), trash view lists it, restore clears it, purge (super/admin) hard-deletes with pre-image audit; public astrologers list excludes unconsented/inactive/deleted; reorder persists `sort_order` and audits once per call.
3. **Consent:** astrologer PATCH can set/clear `listing_consent_confirmed_at` (audited with actor+timestamp); public directory API reflects the gate; FE shows the dated consent control to super/admin/booking_manager only.
4. **Subscribers:** list/search/status-filter/paginate with `meta.total` (gates: viewer+content_editor → 403); unsubscribe flips `unsubscribed_at` (audited); permanent delete removes the row (audited, super/admin only, FE typed-confirm); export sets `X-Export-Capped` when truncated + audit note; dashboard shows "Active subscribers" = confirmed+unconfirmed−unsubscribed and matches a pinned stats test.
5. **Nav:** GET/PUT `/admin/settings/nav` validates shape (bad shape → 400 field errors), audits with diff, fires the deploy hook (mocked in tests, asserted called-once); frontend build merges the DB key over the checked-in fallback, and an unreachable API builds clean on fallback with a warning; `nav.write` 403 for booking_manager/viewer.
6. **Horoscope/blocks:** lang filter filters; any of the 384 rows opens (pagination, no cap); default sort `updated_at desc`; DELETE removes a row (audited, admin+); cron generates yesterday+today+tomorrow rows (unit-pinned); Blocks screen lists every `prefix.*` group and saving a block preserves unknown payload keys (pinned by test).
7. **Permissions:** new endpoints (catalog restore/purge/reorder, settings PUT×engine/non-engine, subscribers list/unsub/delete, nav GET/PUT) × 5 roles = matrix answers; unknown roles fail-safe; rbac test pins `catalog.purge` (super+admin) and that booking_manager keeps catalog CRUD.
8. **Toolchain + QA:** backend suite+lint+tsc green (new: catalog-overhaul, settings-registry, subscribers, nav, horoscope-cap tests); migration 0018 applies on snapshot (additive; consent NULL on all existing rows); frontend biome + astro check + build green; QA sweep: catalog edit/consent/reorder/trash e2e, settings grouped forms + engine-locked + revert, subscribers list/unsub/delete/CSV, nav save → hook → build-merge, horoscope cap/lang/delete, blocks group switch + key preservation; every mutation toasts; every destructive action uses `confirmDialog` (typed where irreversible).
