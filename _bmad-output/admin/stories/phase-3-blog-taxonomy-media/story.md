2. **`POST /admin/posts/bulk`** **[R5]** — `{ids: uuid[], action: 'publish'|'unpublish'|'trash'}`, registered BEFORE the `:id` routes. Contract: (1) validate `ids` — non-empty array of UUIDs, ≤50, deduped → else 400; (2) one pre-read `blog_posts?id=in.(ids)&deleted_at=is.null&select=id,status,slug,title` — any missing id → 404 `{error:{code:'not_found', missing:[…]}}`, **nothing applied**; (3) per-id loop reusing single-PATCH semantics (transition check → PATCH by id → `writeAudit` per post), collecting `{id, ok, error?}`; (4) respond 200 `{data:{results:[…]}}`. A single `.in.` PATCH cannot run per-row `canTransition` nor write per-post audits — the loop is mandatory. Audit: `blog_posts.update` with `bulk: true` for publish/unpublish, `blog_posts.trash` with `bulk: true` for trash (matches existing conventions). Already-trashed ids land in `missing`. Non-durable partial failure (mid-loop DB error) is reported per-id in `results` — successes stay applied and audited. Gated by the existing posts.write subtree.
3. **`POST /admin/posts/:id/restore`** **[R3]** — trash → `deleted_at=null, status='draft'`, and **clears `publish_at` when it is in the past** (a restored post with a past schedule would be silently auto-published by the sweep — the common trash case is a stale scheduled draft). Future `publish_at` is preserved so rescheduling survives trash. Test: restore a row with past `publish_at`, hit the list again, assert still draft. Restore audited.
   **`DELETE /admin/posts/:id?purge=true`** **[R4][R10]** — purge = **super_admin only** via RBAC amendment (below), offered only from Trash: purge on a non-trashed row → **409**. Flow: fetch full row with `deleted_at=not.is.null` → `writeAudit blog_posts.purge` with `details:{before:<full row>, tags:[slugs]}` written BEFORE the delete (the audit row IS the backup; `writeAudit` failure logs server-side per `lib/audit.ts` — accepted) → hard DELETE (post_tags cascades; the only referencing table — `0001:245-247`; `featured_image_url` is plain text, media untouched, `audit_log.entity_id` is text) with `Prefer: return=representation` → empty rows → 404 (idempotent repeat). ## Acceptance criteria (FINAL — review-sharpened, binding)

1. **List:** `GET /api/v1/admin/posts` returns each post with `category:{name,slug}|null` and `author:{display_name|null}` (never a raw UUID) plus `lang`; `lang`, `category_id`, and `deleted=true` filters and `sort ∈ {updated_at, publish_at, title, created_at}` × `order ∈ {asc,desc}` work server-side (publish_at sorts nulls-last, ties break by `id.asc`); `page ≥ 1`, `1 ≤ per_page ≤ 50` enforced; default list excludes soft-deleted rows; URL query state round-trips (reload and back/forward restore filters).
2. **Bulk + audit:** `POST /admin/posts/bulk` `{ids, action: publish|unpublish|trash}` applies server-side in one request; one audit row per changed post (`bulk:true`; trash audited as `blog_posts.trash`); all-or-nothing: empty ids → 400, any unknown or already-trashed id → 404 with `missing:[…]` and zero rows changed; per-id `results` reported; trashed rows disappear from the default list.
3. **Trash lifecycle:** restore returns the row to `draft` with `deleted_at=null` and clears a past `publish_at` (a restored row is never auto-published by the sweep — pinned by test); purge is `DELETE /admin/posts/:id?purge=true`, 403 for every role except super_admin, allowed only on already-trashed rows, removes the row + `post_tags` cascade, 404 on repeat, and its `blog_posts.purge` audit row embeds the full pre-image + tag slugs.
4. **Media:** shipped upload validation stays green (wrong magic bytes → 415; >5 MB → 400; SVG → 400; missing alt → 400 — existing tests are the regression pins); `GET /admin/media` gains sanitized `q` (path/alt ILIKE) and per-row `used_in` (exact `featured_image_url`/`og_image_url` + `content_md` path match; trashed posts count) and returns `items` matching the page; `DELETE /admin/media/:id` with `used_in>0` → 409 `{used_in:n}`; `?force=true` requires `media.force_delete` (super_admin/admin only — content_editor 403) and deletes the Storage object then the row; repeat delete → 404; delete audited.
5. **Markdown:** route test: a post created with `<script>` in `content_md` stores the sanitized version; lib unit tests for `sanitizeMarkdown` stay green; blocks PUT passes every string payload value through `sanitizeMarkdown` (route test pins it); public render pipeline (`renderArticle` + rehype-sanitize) untouched.
6. **Taxonomy:** category PUT updates name/slug/name_hi/description/display_order (slug collision → 409); category DELETE with ≥1 non-trashed referencing post → 409 `{posts:n}` and deletes after reassign; tag rename keeps slug unless changed (collision → 409); `POST /admin/tags/merge` (super_admin/admin; `source_id == target_id` → 400) moves associations — a post holding both tags ends with only the target link — deletes the source, audits `blog_tags.merge` with moved/replaced counts; all deletes/renames audited with pre-images; new columns round-trip.
7. **Permissions:** every new endpoint (bulk, restore, purge, category/tag PUT+DELETE, tags merge, media DELETE + force) × all 5 roles returns the matrix answer; unknown/legacy roles fail-safe with zero capabilities; the pinned rbac test asserts the amended admin set (no `posts.purge`) and `media.force_delete` placement.
8. **Toolchain + QA:** full backend suite + lint + typecheck green; migration 0017 applies on a snapshot (lang backfills `en`; new columns inherit existing RLS, no policy changes); frontend `astro check` 0 errors, biome clean, build green; QA sweep: posts list vs Sally tokens; bulk → trash → restore → purge e2e; media upload happy path + delete/force e2e; editor preview/autosave/confirm-dialog; taxonomy edit/merge screens.
