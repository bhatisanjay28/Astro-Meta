## Story

**As the** owner of Vyotish, **I want** a hover dropdown (mega menu) on the 9 main tabs — Consultations, Horoscope, Panchang, Muhurat, Astrology, Poojan, Free Calculators, Gemstone and Blog — **so that** visitors can jump straight to any sub-section from the home page (and every page) without passing through each hub first.

**Why now:** the header's 9 flat tabs under-expose ~300 prerendered pages (23 calculators, 12×6 horoscope pages, city pages, learn articles) that are currently one hub-click deep.

## Scope — frontend repo only

- `src/data/navigation.ts` — one config file: `NavTab` gains optional `menu?: MenuGroup[]`; add menus for the 8 tabs that have real sub-sections. Single source for desktop mega + mobile accordion.
- `src/components/Header.astro` — desktop mega panels (hover + keyboard + delays), mobile/touch accordion in the existing drawer, styles from site tokens.
- **Out of scope:** Footer/ExploreTiles (keep flat tab lists), any backend/API change, new pages, anchor ids added to hub pages (Muhurat's existing `#today-h`/`#finder-h` are used as-is).

## Acceptance criteria (owner directive, verbatim, each AC 1:1)

### AC-1 Hover dropdowns for the 9 tabs
> "add a hover dropdown (mega menu) for our 9 main tabs … When the mouse moves over a tab, show its sub-categories in a dropdown, and clicking one takes the user to that section's page."

Desktop nav items become wrapper `<li>`s: the tab link still navigates to the hub on click; hovering the wrapper opens a panel of that tab's sub-categories (links to the real routes in inventory). Menus: Consultations (directory/booking), Horoscope (12 signs grid), Panchang (popular cities), Muhurat (today + finder), Astrology (kundli/matching/compatibility/learn), Poojan (popular pujas), Free Calculators (4 groups × 23 tools), Blog (categories/RSS). **Gemstones has no sub-pages — it renders as a plain link with its "Soon" chip, no dropdown (honest empty behaviour).** Every panel leads with the tab hub as its first "Overview" link.

### AC-2 Small open/close delay, stays open into the panel
> "Add a small open/close delay so the menu doesn't flicker, keep it open while the mouse moves into it"

JS pointer handlers on each wrapper: opens after **100 ms** hover, closes after a **250 ms** grace period; moving into the panel keeps it open (shared wrapper enter/leave, timers cancelled on re-enter); moving directly between tabs switches cleanly (each wrapper's timers are independent; opening one closes the others).

### AC-3 Keyboard + screen readers
> "support keyboard and screen readers"

Tab link carries `aria-expanded` + `aria-controls`; receiving focus opens the panel immediately (no delay); leaving focus closes it; **Escape** closes and returns focus to the tab; **ArrowDown** from the tab moves focus to the first panel link. Panels are labelled (`aria-label="{Tab} submenu"`), links are a real `<ul>` list, focus-visible rings per site token. Tab-through order is DOM order (open panel is not hidden from AT — `visibility` gated so links are only tabbable while open).

### AC-4 Accordion on mobile and touch
> "use an accordion menu on mobile and touch devices"

Desktop mega behaviour is gated to `(min-width: 1280px) and (hover: hover) and (pointer: fine)`; below that — and on any `hover: none` device at any width — the existing hamburger drawer shows the 9 tabs with per-tab accordion disclosure (chevron toggle, `aria-expanded`, hub "Overview" first, then the same sub-links from the one config). Drawer keeps its current open/Escape/focus behaviour.

### AC-5 One config file
> "Drive the menu from one config file"

`navigation.ts` holds every group/link (label, href, optional description); both desktop panels and the mobile accordion render exclusively from it — no duplicated link lists anywhere.

### AC-6 Match site style
> "match our site's style"

Panels/accordion use the design-token utilities already in the header (`bg-light-surface`/`dark:bg-dark-surface`, `primary-container` chips, `--radius-card` 12px, gold accents, Material Symbols, font-display group titles). Design pass via Sally/Stitch first; colours re-mapped to tokens (per Sally pattern: never hardcode Stitch hexes).

### AC-7 No overflow, never hidden behind content
> "make sure it doesn't overflow or hide behind other content at any screen size"

Panels are absolutely positioned to the header container (`left-0 right-0`, inside `max-w-7xl`) so they can never exceed the viewport at any width ≥1280px; solid surface background, border, elevated shadow, `z` above page content (header stacking context); verified at 1280/1440/1920 and drawer at 360/768/1024.
