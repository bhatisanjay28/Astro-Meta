## Story

**As the** owner of Vyotish, **I want** every "Place of birth / Place / City" field to behave like a modern search-select — clear button, type-to-replace, and state that can never hold a stale place — **so that** changing a city is effortless and no form can ever submit a selected place's coordinates with different free text.

**Why now:** owner complaint — after selecting a city, changing it requires manually deleting the old text before typing a new one.

## Scope — frontend repo only

`src/components/PlaceField.astro` (markup + styles), `src/scripts/place-picker.ts` (behaviour), `src/pages/calculators/[tool].astro` (submit guard: free-text block for the optional-place case). **No other consumer changes** — all 12 instances already render the shared component; page submit guards already read hidden role values, which stay authoritative.

**Explicitly out of scope (inventory §B):** `BookingForm.astro:93` `bk-location` is a free-text venue/mode note sent as a plain string — converting it would change the booking payload shape (owner rule: data shape unchanged). `QuickKundli.astro` is dead code (zero imports) — untouched.

## Acceptance criteria

Owner requirement ①–⑧ quoted; each AC maps 1:1.

### AC-1 Clear (×) button
> ① "once a city/place is selected (or any text is entered), show a cross icon inside the input on the right. Clicking it clears the text AND the stored selection, puts focus back in the input, and opens the suggestion list (or shows the placeholder)."

`PlaceField.astro` renders `<button type="button" class="pp-clear" data-place-clear aria-label="Clear city" hidden>` inside a new `.pp-box` wrapper (input + button + listbox). `place-picker.ts` toggles visibility whenever the input holds text (`syncClear()`), and on click: wipes input text, all hidden role values, selection state; resets the field's Places session + suggestions; sets `aria-invalid="false"`; announces via the existing `role="status"` live region; refocuses the input (placeholder shows — with an empty query there are no suggestions to list, per the "or shows the placeholder" branch). `mousedown` is prevented on the button so focus never leaves the input.

### AC-2 Typing replaces the old value
> ② "on focus (or click), the existing text is fully selected, so the first keystroke replaces it, and if the user edits the text in any way after a selection was made, the previously selected place is invalidated immediately."

`focus`/`click` → `input.select()` when the input holds text. Any `input` event (typing, paste, cut) after a selection → immediate invalidation: hidden roles wiped, `data-place-selected` removed from the wrapper, field Places session regenerated, suggestions list reset, ✓ status cleared. (Hidden-role wipe on edit already existed — now it also clears selection state and the session.)

### AC-3 State stays consistent
> ③ "clearing or editing must also clear the structured data tied to the selection (placeId, city, state, country, latitude, longitude…) … also reset the session token and the suggestions list."

All structured data is the hidden role inputs (`lat`/`lng`/`tz`/`combined`/`place_id`) — one `clearRoles()` wipes exactly those. Session is **per field** (was one per page load) and regenerates on clear and on edit-after-selection; `items = []` on both. Page guards keep reading role values → old city can never submit with new text.

### AC-4 Validation
> ④ "if the user types but doesn't pick a suggestion, show an error such as 'Please select a city from the list'. A field must not appear valid while holding free text that isn't a selected place."

On blur (when focus truly leaves the field — in-field blurs to list/clear are excluded): free text + no selection → `aria-invalid="true"` on the input, red border, status "Please select a city from the list." Selection or emptied text clears the error. `calculators/[tool].astro` guard additionally blocks submit when the optional-place field holds free text without a pick (required forms were already blocked via empty roles).

### AC-5 Keyboard + accessibility
> ⑤ "Esc clears the suggestion list (second Esc clears the field), the × button is focusable with an aria-label like 'Clear city', arrow keys and Enter still work for suggestions, and a screen reader announces when the field is cleared."

Escape: list open → close; list closed + text → clear field (announce + refocus). × is a real `<button>` (Tab-reachable, `aria-label="Clear city"`). Arrows/Enter unchanged; list options get `tabindex="-1"` so Tab skips the listbox (arrows are the a11y path). Cleared/selected/error messages all flow through the `role="status" aria-live="polite"` status line.

### AC-6 Mobile + layout
> ⑥ "the × button has at least a 44px tap area, doesn't overlap long city text (add right padding to the input), and is aligned consistently with the input's height."

`.pp-clear` is absolutely positioned inside `.pp-box`, `min-width:44px`, full input height (input is `min-height: var(--target-min, 44px)`), vertically centred icon; input gets `padding-right: 46px` (`has-clear` class) only while the button is visible. Verified at 360px.

### AC-7 Edit mode
> ⑦ "when a form opens with a saved city, show it pre-filled with the × button visible. Editing and clearing behave exactly as above."

New additive `PlaceField` props: `prefill?: { label: string; coords: string; place_id?: string }` (SSR-renders visible text + role values + `data-place-selected="true"`), plus `disabled`/`readOnly` passthrough. At init the script adopts prefill state (selected ⇔ visible text AND resolved roles — so `muhurat`'s hidden-only New Delhi default keeps today's empty-look behaviour). For future dynamically-injected forms the script exposes `window.vyPlacePicker.rebind()`. No current consumer renders a prefill — covered by e2e via the rebind seam.

### AC-8 Disabled / read-only
> ⑧ "don't show the × button."

× is not rendered for `disabled`/`readOnly` fields; the script binds no listeners and validation never fires.

### AC-9 No regressions
Payload shapes and the `place:selected` event (detail: lat/lng/tz/label/place_id/slug) unchanged; all 12 instances keep their flows — kundli submit, home Kundli/Panchang widgets, matching (2 independent fields), muhurat today reload + finder, panchang slug navigation, calculators (birth / transits / date-place kinds). Existing suites green: `qa/e2e-s14-calculators.mjs`, `qa/e2e-calculators-regressions.mjs`, `qa/e2e-contrast.mjs`.

### AC-10 Tests + responsive verification
New `qa/e2e-place-picker.mjs` (same harness: Bun + playwright-core, preview :4321): select → replace-by-typing → ×-clear; role/state/session invalidation on edit; submit blocked on free text; prefill edit mode; keyboard (Esc ×2, Tab to ×, arrows, Enter); matching independence; muhurat default + reload; panchang navigation; axe on the field in light+dark; full-page shots at 360/768/1024/1440 on every surface (empty, list-open, selected+×, error states).

## Test notes (enrichment)
- Free-text blur validation must not fight the 150ms blur-close timer: validation runs inside it and bails when focus is still inside the field.
- Escape clearing must not fire while the list is open (first Esc = close only).
- `input.select()` on click: after focus-select, a second click re-selects — per requirement ②, click behaves like focus.
- Session semantics (Google Places billing): a session = query → pick; regenerating on clear/edit-after-pick is correct.

## QA review (self, pre-commit) — VERDICT: APPROVED, 2026-11-22
- Event contract `place:selected` untouched → muhurat/panchang/HomePanchang consumers unaffected.
- `.pp-list` now anchors to `.pp-box` (directly under the input) instead of the whole `.pp` column — visual improvement, dropdown no longer offsets below the status line; same z-index/width behaviour.
- Options `tabindex="-1"`: arrows/Enter remain the selection path; nothing else changes.
- Disabled fields: button not rendered (SSR) AND script returns early (defence in depth).
- **Review catch 1 (fixed)**: Chrome finalises mouse-caret placement *after* the click handler, collapsing a synchronous `select()` — select-all on focus/click is deferred one tick (`scheduleSelect`).
- **Review catch 2 (fixed)**: after a pick, `lastQuery` still held the picked query — retyping the *same* query skipped the fetch and the list never opened; `lastQuery` now resets when a consumed selection is invalidated (regression case P-02d).
- **Review catch 3 (harness)**: char-by-char typing opened a multi-render window where a stray blur could close the list between renders — `pick()` uses one `fill` input event and selectors scoped to an *open* list.
- **Discovery (no change, by design)**: /panchang "New Delhi" resolves to `city:new-delhi-delhi` (the capital row) while the card is `/panchang/new-delhi` ("Delhi" row) — two distinct GeoNames rows; the honest "no dedicated page" fallback is the designed behaviour (P-10b). Mumbai (`city:mumbai`) navigates (P-10a).
