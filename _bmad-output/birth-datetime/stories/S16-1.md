# S16-1 — One reusable date & time picker for every date/time field on the site — Epic 16 story 1 of 1

> Written by Bob (SM) 2026-11-22 · Source: **owner directive 2026-11-22** (verbatim requirements quoted in ACs below) + field inventory `_bmad-output/birth-datetime/inventory.md`.
> **BMAD review: APPROVED (self, 2026-11-22)** — one new shared component (`DateField.astro` markup + `date-time-picker.ts` behaviour) replaces every `type="date"`, `type="time"` and `datetime-local` input site-wide (19 instances, 10 files); every page's value-reading contract survives unchanged because the component keeps `name`/`id`/data-attrs on a **hidden input** that always holds the backend format (ISO `YYYY-MM-DD`, `HH:MM`, `YYYY-MM-DDTHH:MM`) and dispatches `input`/`change` on sync; the only page-script edits are the three programmatic writers (PanchangDetail ×2, admin prefill ×1) which move to the exposed `window.vyDateTime.set()` seam; all new UI is token-based with literal fallbacks (place-picker pattern) so it works in the tailwind pages, the legacy CSS-var pages, the Admin layout and both themes; scope expansion to ALL fields (owner follow-up) is covered by the inventory and the per-mode config.

## Story

**As the** owner of Vyotish, **I want** every date and time field on the site — DOB, birth time, booking dates, panchang/muhurat lookup dates, calculator extra dates, and the admin publish scheduler — replaced by one fast, clear, accessible picker consistent with our design system, **so that** data entry is quick on mobile and desktop, impossible/future birth dates are caught at the field, and every field looks and behaves the same everywhere.

**Why now:** owner complaint — the native browser pickers have poor style and a poor selection experience (desktop native popups are inconsistent, mobile keyboard is not numeric, no visible month/year jumps, no validation until submit).

## Scope

- **New:** `src/components/DateField.astro` (SSR markup for all modes) + `src/scripts/date-time-picker.ts` (behaviour, calendar popup, validation, style injection) + unit tests `qa/unit/date-time-picker.test.ts`.
- **Consumers (swap input → component):** HomeKundli, kundli.astro, matching.astro, calculators/BirthForm.astro (+extraFields), calculators/[tool].astro (inline form + extraFields + registry `dateMode` flags), QuickKundli (dead code, 2-line swap), BookingForm ×2, BookingModal, PanchangDetail (+2 seam lines), muhurat/index ×2, admin/posts/edit (+1 seam line).
- **No backend changes** — hidden-input values are byte-identical to what native inputs sent (ISO date, `HH:MM`, datetime-local). No payload shapes change.

**Explicitly out of scope:** BookingForm `bk-time` free-text preference note; adding new min/max business rules to booking/muhurat dates (mode `free` keeps today's behaviour); muhurat/booking page logic.

## Acceptance criteria

### AC-1 Typeable DD/MM/YYYY with numeric keypad on mobile
> "a typeable DD/MM/YYYY input (numeric keypad on mobile)"

`DateField mode="date"` renders three segment inputs (DD, MM, YYYY) — each `inputmode="numeric"` `pattern="[0-9]*"` `autocomplete="off"`, grouped in a `role="group"` with `aria-label` from the field label. Typing auto-advances (2 digits, or first digit >3 in DD / >1 in MM auto-pads `0X` and advances); Backspace on an empty segment moves back; ArrowUp/Down increment/decrement with rollover; paste of `15/08/1990`, `15-08-1990`, `15081990` or `1508 1990` distributes across segments. No native `type="date"` remains anywhere.

### AC-2 Optional calendar popup with month/year dropdowns, newest year first, 100 years back
> "plus an optional calendar popup with month and year dropdowns (newest year first, 100 years back)"

A calendar-icon trigger button sits inside the field; opening shows a non-modal popup (`role="dialog"`, week-day header, day grid) with a **month `<select>`** and a **year `<select>`** listing `currentYear → currentYear−100` **newest first** (birth mode) or `1900 → 2100` (free mode); prev/next month buttons disable at range edges; today is marked (`aria-current="date"`) with a "Today" shortcut; picking a day fills the segments, syncs the hidden value and closes; the popup flips above when the viewport has no room below and never exceeds `min(21rem, 100%)`.

### AC-3 Impossible and future dates rejected with clear messages
> "Validate impossible and future dates with clear messages"

Validation runs as segments complete (all three filled) and on submit:
- impossible → **"31 February 2001 doesn't exist — February 2001 has 28 days."**
- future in birth mode → **"The birth date can't be in the future."**
- older than 100 years in birth mode → **"Please enter a year within the last 100 years (1926–2026)."**
- incomplete on submit when required → **"Please enter a complete date (DD/MM/YYYY)."**

Error text sits under the field (token `--color-error-text`, paired with a ⚠ label so it never relies on colour alone), the wrapper gets `aria-invalid`, the segments get `aria-describedby` → the message, and the hidden input stays empty while invalid. Messages clear the moment the entry becomes valid.

### AC-4 Time field gets the same treatment
> "Do for time field as well"

`DateField mode="time"` renders HH : MM segments (+ AM/PM toggle, keyboard-operable and typeable via `a`/`p`, default 12-hour for birth times; `hour12={false}` renders 24-hour for the moon-phase UTC field). Hidden value is always 24-hour `HH:MM` (byte-identical to native). Messages: "Hour must be 1–12." / "Minutes must be 00–59." / "Please enter a complete time, or clear it." Optional fields with partially-typed segments block submit with that message instead of silently dropping.

### AC-5 Backend value stays ISO
> "keep the backend value as ISO YYYY-MM-DD"

Every visible segment is name-less; a hidden input carries the consumer's `name`/`id`/data-attributes and holds `YYYY-MM-DD` (date), `HH:MM` (time), `YYYY-MM-DDTHH:MM` (datetime). The script dispatches bubbling `input`+`change` on the hidden input at every sync, so FormData consumers (kundli, matching, BirthForm/[tool], muhurat, BookingForm) and `.value` readers (HomeKundli, BookingModal, [tool] guard) work with zero changes.

### AC-6 One reusable component applied to every date/time field
> "Build one reusable component, apply it to every DOB field and time field" + follow-up "all date and time fields available in website"

One component, `mode="date"|"time"|"datetime"`, `preset="birth"|"free"` (future/100y rules), props: `name`, `id`, `value`, `required`, `hour12`, `label`, `attrs` (e.g. `data-dob`). Applied to **all 19 instances in the inventory** (A1–A6, B1–B5, C1–C3, D1) — a post-swap `grep type="date"|type="time"|datetime-local` over `src/` returns zero matches.

### AC-7 Responsive, keyboard accessible, on-theme
> "make it responsive and keyboard accessible"

Segments ≥44px targets, popup clamps to viewport width (360px verified); Tab order DD→MM→YYYY→(AM/PM)→trigger; popup: arrows move the focused day (month rollover re-renders), PageUp/PageDown ±1 month, Enter picks, Esc closes and refocuses the trigger, focus returns on outside-interaction close; trigger carries `aria-haspopup="dialog"` + `aria-expanded`. Styling uses the design tokens (`--color-border-strong` interactive borders ≈6:1, `--focus-ring`, `--radius-card`, `--target-min`) with literal fallbacks — light/dark both AA (contrast e2e re-run).

### AC-8 Admin scheduler + programmatic writers keep working
> scope expansion covers D1

`mode="datetime"` composes date+time groups into one hidden `id="publish_at"` input (`YYYY-MM-DDTHH:MM`); `window.vyDateTime.set(el, value)` re-renders segments from the backend format (used by admin prefill and PanchangDetail's init/prev/next writes), and `window.vyDateTime.rebind()` covers dynamic hosts (BookingModal).
